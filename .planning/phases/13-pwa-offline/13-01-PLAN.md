    **Part B — Create `src/composables/useOnline.ts`:**

    A Vue composable that provides reactive online/offline state and triggers sync on connectivity restore. Per D-05 (automatic background sync) and D-12 (sync without intervention):

    ```typescript
    import { ref, onMounted, onUnmounted } from 'vue'
    import { useSyncStore } from '@/stores/sync'

    export function useOnline() {
      const isOnline = ref(navigator.onLine)

      function handleOnline() {
        isOnline.value = true
        // D-05 / D-12: trigger sync automatically when coming back online
        const syncStore = useSyncStore()
        syncStore.manualSync()
      }

      function handleOffline() {
        isOnline.value = false
      }

      // Fallback for Safari/Firefox (no Background Sync API support)
      function handleVisibilityChange() {
        if (document.visibilityState === 'visible' && navigator.onLine) {
          const syncStore = useSyncStore()
          syncStore.refreshPendingCount()
          if (syncStore.pendingCount > 0) {
            syncStore.manualSync()
          }
        }
      }

      let periodicTimer: ReturnType<typeof setInterval> | null = null

      onMounted(() => {
        window.addEventListener('online', handleOnline)
        window.addEventListener('offline', handleOffline)
        document.addEventListener('visibilitychange', handleVisibilityChange)

        // Periodic sync check every 5 minutes as additional fallback
        periodicTimer = setInterval(() => {
          if (navigator.onLine) {
            const syncStore = useSyncStore()
            if (syncStore.pendingCount > 0) {
              syncStore.manualSync()
            }
          }
        }, 5 * 60 * 1000)
      })

      onUnmounted(() => {
        window.removeEventListener('online', handleOnline)
        window.removeEventListener('offline', handleOffline)
        document.removeEventListener('visibilitychange', handleVisibilityChange)
        if (periodicTimer) clearInterval(periodicTimer)
      })

      return { isOnline }
    }
    ```

    Note: `useSyncStore` is referenced but its implementation (stores/sync.ts) will be created in Plan 02. The composable will be wired in main.ts in Plan 02's integration task. This is a forward reference — ensure the import path is correct.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Service Worker | SW intercepts all fetch requests; untrusted responses could be cached |
| IndexedDB → App JS | All JS on the same origin can read/write IndexedDB data |
| Sync Queue → Internet | Queued operations with stale session tokens could be replayed |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-01 | Tampering | Service Worker (sw.ts) | high | mitigate | HTTPS required for SW registration (browser enforces). SW file served with no-cache headers (nginx config). Content hash in precache manifest prevents stale SW. |
| T-13-02 | Information Disclosure | IndexedDB (Dexie) | medium | mitigate | No sensitive auth tokens or PII stored in entity caches. Sync queue stores operation payloads that may contain internal data — same-origin policy limits exposure. |
| T-13-03 | Spoofing | Sync queue replay | medium | mitigate | Session token expiry detection: on 401 during sync replay, pause queue, prompt user to re-authenticate. Never retry with stale tokens (api.ts interceptor + sync service). |
| T-13-04 | Repudiation | Offline operation recording | medium | mitigate | Server validates idempotency via X-Idempotency-Key header. All write operations include `updated_at` timestamp for conflict detection. |
| T-13-05 | Spoofing | Forward reference to useSyncStore | low | accept | useOnline.ts imports stores/sync.ts which does not exist until Plan 02. The import will resolve at runtime. Type-check file list in Plan 01 excludes stores/sync.ts. |
| T-13-SC | Tampering | npm/pip/cargo installs | high | mitigate | All packages verified [OK] in RESEARCH.md Package Legitimacy Audit. No blocking-human checkpoint required per [OK] verdict on all packages. |
</threat_model>
